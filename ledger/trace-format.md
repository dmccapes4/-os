# κύριος trace format v0.0.1

**Status:** bones. Every receipt is one JSON object on one line. The ledger is append-only; a correction is a new receipt whose `parent_hash` names the line it answers.

**Scope:** v0.0.1 proves the shape on `lirvol`. Eviction fields are present from the start so the format can carry the decay-to-external-storage lifecycle later without a schema migration.

---

## Required fields

| Field | Type | Meaning |
|---|---|---|
| `receipt_id` | string | UUID, deterministic for this line. Generated by `ledger/receipt.py` if omitted. |
| `version` | string | Schema version; for v0.0.1 use `"kyrios-trace-v0.0.1"`. |
| `space` | string | Name of the space the arrival touched. |
| `port` | integer | Port number of the space. |
| `key_fingerprint` | string | SHA-256 fingerprint of the key used to arrive. Empty string for local/operator actions. |
| `action` | string | One of: `arrive`, `grant`, `refuse`, `evict`, `audit`, `suggest`. |
| `processor` | string | Path or name of the processor-document that caused the action. |
| `document_hash` | string | SHA-256 of the processor-document as it existed at execution. |
| `parent_hash` | string | SHA-256 of the parent receipt, or `"root"` for the first receipt in a chain. |
| `timestamp_utc` | string | ISO-8601 UTC timestamp. |
| `clew` | list of strings | Source documents that justify this receipt (paths, not prose). |
| `eviction_status` | string or null | `null`, `pending`, or `evicted`. |
| `eviction_location` | string or null | Path or URI where the evicted payload lives; `null` while in hot storage. |

## Optional fields

| Field | Type | Meaning |
|---|---|---|
| `payload_hash` | string | SHA-256 of any output artifact produced by the action. |
| `operator_decision` | string | Name of the operator gate and the decision (`operator-granted-build`, etc.). |
| `notes` | string | Short, factual note; never a replacement for the clew. |

## Eviction semantics

- Hot storage is the NVMe ledger on `lirvol`.
- When a receipt is copied to external storage, append a new receipt with `action: evict`, `eviction_status: evicted`, and `eviction_location` set.
- The original receipt line is **not edited**. Its `eviction_status` remains `null`. The eviction receipt is the correction.
- This mirrors `PortalVision/scripts/evict_receipts_to_external.py`, which copies only and leaves an eviction notice.

## Validation

`ledger/receipt.py` checks:

1. The line is valid JSON.
2. All required fields are present and typed correctly.
3. `action` is in the allowed set.
4. `document_hash` matches the file at `processor` if the file exists.
5. The line is appended, never inserted or overwritten.

## Receipt chain

A chain is a sequence of receipts linked by `parent_hash`. The first receipt in a chain uses `parent_hash: "root"`. A correction names the hash of the receipt it corrects. This gives κύριος the property the CVE report calls for: *"what did you used to say?"* is answerable without rewriting history.
